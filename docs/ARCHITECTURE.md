# 架构与维护约定

## 设计边界

应用由 React 19 + TypeScript、Canvas 2D 图像引擎和 Express 5 API 组成。前端与 API 使用同一端口，开发时 Express 挂载 Vite，生产时提供构建后的静态资源。依赖锁定在 `package-lock.json`，字体随构建打包，不依赖第三方字体网络请求。

浏览器处理艺术作品的确定性部分，模型处理可替换的推荐部分。服务端失败不能阻断手动设置、像素处理或导出。

## 数据流

1. `loadAsset` 校正 EXIF 方向，取得实际展示宽高，生成界面缩略图。持有 `ImageBitmap`，替换/卸载时释放。
2. `EditorSettings` 保存比例、归一化裁剪框、选色、形状、布局参数、外围宽度、手动孔位与两个独立随机种子。颜色/形状的 `null` 表示未选择；裁剪的 `null` 表示默认居中，`sourcePositions` 的 `null` 表示自动孔位。临时预览值不写回用户设置，也不触发推荐。
3. `createScene` 输出与分辨率无关的场景：画面比例、孔径、每个孔的源位置、目标位置和旋转角。预览与导出共享这一场景。
4. `renderArtwork` 从原始位图重建两张基础画布，再逐块进行蒙版交换，最后拼接。预览与导出只改变输出分辨率。
5. 推荐请求独立于布局与导出。完成的推荐需要用户采用，不能主动覆盖用户设置。

## 图像不变量

- `crop` 使用 EXIF 校正后原图的 0–1 坐标。`domain/crop.ts` 的 `photoCrop` 是预览、AI 输入、原图导出尺寸和渲染的统一像素选区来源。自由比例来自选区的真实宽高；预设比例在选区内等比裁切。色纸仍按目标比例独立居中覆盖。
- 裁剪窗口只维护草稿，采用 Pointer Capture 处理越出手柄的拖动，纯函数负责移动、缩放、固定比例与边界约束。应用时一次提交比例和选区；取消不更新编辑状态。
- 场景使用高为 1、宽为画面宽高比的统一坐标。孔径以短边比例定义。
- `sourcePositions` 按裁剪后照片宽、高分别归一化为 0–1，数组索引与碎片对应。`domain/holes.ts` 负责移动、边界约束和自动位置快照；只更新指定孔，不修改目标碎片。改变数量或源布局时清空手动位置，裁剪/比例变化时保留相对位置。
- `targetPositions` 按整张色纸的宽、高归一化为 0–1，包含外围扩展区域。`domain/fragments.ts` 负责目标位置快照和旋转外接圆约束；外围中央照片为禁入区，越入时投影至最近的有效边界。手动目标位置不再次经过矩阵洗牌。源孔与目标碎片可独立恢复自动布局；改变孔数同时重置两侧，源孔重排不重置目标位置。
- `domain/composition.ts` 是预览、导出尺寸和交互坐标的统一来源，返回照片、色纸和组合画布的像素矩形。`HoleOverlay` 使用同一几何，观察 Canvas 的显示尺寸并映射 Pointer Events；Pointer Capture 保持拖动，取消时恢复整组原位置。Canvas 尺寸和交互几何在同一次布局更新中切换。
- 拖动层对每个源孔和目标碎片提供独立交互节点，`PieceSide` 决定使用照片或色纸的坐标原点；目标轮廓显示真实旋转角。两侧复用 Pointer Capture、键盘微调和取消逻辑，取消只恢复开始拖动时该侧的手动位置。
- 外围模式的源位置仍以照片左上为原点，目标位置以外围色纸左上为原点；`scene.border` 表示以照片高度为单位的四边宽度。`domain/surround.ts` 沿矩形周长排布，按旋转外接圆限制孔径和抖动，保证碎片处于外围区域且满足不重叠设置。
- 形状定义为中心在原点的 100 × 100 SVG 路径。SVG 图标与 Canvas 蒙版使用相同路径。
- 使用 `evenodd` 填充规则，眼睛中心等内部镂空不参与交换。
- 每个孔与一块碎片对应，数量守恒；空间不足时缩小孔径并显示原因，不丢弃碎片。
- 照片与色纸的基础画布不可变。照片孔位从目标位置的原始色纸取样，碎片从源位置的原始照片取样；旋转采用互逆变换。
- 外围模式的色纸始终为纯色，照片孔位直接填同一颜色；上传纹理仅用于主色提取。色纸独立导出清空中央照片矩形，组合导出在此处放回打孔照片。拖动辅助线只属于交互 SVG，不进入作品像素。
- 不从已加工的输出画布取样，避免把之前的碎片再次采入后续碎片。
- 照片随机孔位使用 `sourceSeed`，碎片位置、排列和旋转使用 `fragmentSeed`。更换颜色不会改变几何位置。
- 自动不重叠布局按旋转后外接圆保守排布。拥挤情况下使用抖动网格确保指定数量全部容纳。手动孔位允许重叠，但仍受照片边界约束。

## 推荐协议

请求包含图片预览，以及已经指定的颜色、形状或色纸图片。前后端共用 Zod 协议，服务端再次验证图片真实内容。

| 输入             | 返回                         |
| ---------------- | ---------------------------- |
| 仅照片           | 颜色 + 形状                  |
| 照片 + 形状      | 颜色                         |
| 照片 + 色纸/颜色 | 形状                         |
| 手动指定三项完整 | 前端不请求，API 拒绝冗余调用 |

模型适配器使用 Chat Completions API，发送真实 `image_url` 图片块，启用 JSON 输出。DeepSeek 模式默认使用 `deepseek-flash` 并关闭思考模式；兼容模式不发送厂商专有的 `thinking` 参数。每次返回三组候选，形状在内置白名单中，颜色为六位 HEX，理由为有限长度的文本。

服务端重新组装结果，只保留缺失参数。即使模型返回已锁定字段，也不会传给客户端修改。外部错误体不转发到浏览器。

推荐仅由生成/重试按钮的点击事件发起，Effect 只负责清空过期候选和中止旧请求，不能发送请求。同步 `AbortController` 引用阻止连续点击产生重复请求；加载中禁用生成按钮。素材、裁切比例或手动选择的颜色/形状变化时作废旧结果，布局编辑不影响候选。替换素材加载期间不能发起推荐。旧请求的结束不能释放新请求的锁，迟到响应不能回写界面。中止浏览器请求不保证撤销已经发往模型的计费调用。

每批候选保存原始补全范围 `scope`、当前采用索引和预期编辑上下文 `contextKey`（素材 ID、裁切比例与选区、加载状态、色纸模式、颜色与形状）。采用候选会在同一次 React 更新中推进预期上下文和编辑设置，保留三组候选；后续切换只修改 `scope` 中的字段。手动修改使上下文不匹配，旧候选立即隐藏并清理，不能继续覆盖手动设置。再次生成沿用原补全范围，请求中只发送生成前已锁定的参数，不能把上次推荐的值误认为新锁定项。

颜色与形状可单独取消，也可原子地清空两项及色纸素材；这些操作只更新本地编辑状态。清空色纸还会作废正在加载的色纸，避免迟到上传覆盖清空状态。内置灵感直接在本地生成，不依赖推荐接口。不自动重试计费请求。相同完整输入的有效结果在服务端缓存 10 分钟，最多 32 项。

模型请求超时 45 秒，按 IP 每分钟最多 8 次。API 限制 JSON 体积、预览字段长度、图片像素数与格式，并验证浏览器同源请求。密钥仅由服务端的环境配置或私有本机配置存储读取。

## 本机模型配置

`shared/llm-config.ts` 定义地址、服务类型、模型与密钥操作协议。`server/llm-settings.ts` 加载环境默认值与优先级更高的 `.local/llm.json`，对外只提供不含密钥的 metadata 和推荐函数。配置 API 限制本机连接，PUT 校验同源、JSON 大小和修订号。

API Key 采用 `keep` / `replace` / `clear` 显式语义，清空状态也持久化。更换地址不能隐式复用旧密钥。更新先写权限为 `0600` 的临时文件，再原子替换，成功后才更新内存配置和重建缓存。写入失败保持旧配置；损坏配置禁止静默回退。模型请求不跟随重定向，避免凭证被带往另一个服务。

配置窗口以 password 输入接收新密钥，不回显旧密钥、不写浏览器存储，关闭时卸载草稿。保存不会连接模型。修改配置后取消当前未完成的推荐请求，但保留已完成候选和图像编辑状态。配置接口和推荐接口的自动化测试使用临时文件或模拟响应，不修改开发者的私有配置。

Git 忽略环境变量、`.local`、`.release`、私人素材和生成产物，Vite 禁止读取私有目录。发布脚本检查暂存区后用同一个 Git tree 打包，CI 复用检查器。细节见 [SECURITY.md](../SECURITY.md)。

## 扩展方式

- **新形状**：扩展 `shared/contracts.ts` 中的枚举和 `src/domain/shapes.ts` 中的路径；增加内部镂空或边界测试。模型自动获得更新后的白名单。
- **新比例**：扩展 `RATIOS`；自动裁切通过最小对数宽高比差确定，即最大保留面积。
- **新布局**：扩展布局类型及 `createScene` 的纯函数分支，返回同一场景结构，不在 React 组件中直接操纵像素。
- **替换模型服务**：实现 `Recommender` 接口，保持请求/响应协议，不影响图像处理。
- **草稿保存**：后续保存明确版本的设置与资产引用，避免把浏览器 `ImageBitmap` 直接序列化。首次加入时应设计迁移方案。
- **更大图片/连续拖动性能**：目前预览在主线程按动画帧渲染；后续可将同一场景模型送入 Worker/OffscreenCanvas，无需重写布局算法。

## 质量约定

TypeScript 严格模式与索引访问检查开启。`npm run check` 是提交前的基础检查；改动图像、编辑状态或导出时还应运行浏览器测试。CI 自动执行基础检查、格式检查及 Chromium 验收，不需要真实 API 密钥。

单元测试验证几何不变量，不依赖截图像素的偶然排版。浏览器像素测试使用有明确颜色分区的合成图，验证精确裁片、色纸回填、互逆旋转与镂空中心。用户提供的九张照片作为可选本地验收素材，CI 不要求携带私人图片。

公开部署、多人使用、持久化存储和跨浏览器性能优化属于后续版本范围，当前不通过隐式依赖预先加入这些能力。
